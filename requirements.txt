# piqs/parser.py parses Java with tree-sitter. Both versions are PINNED, not floated: the
# tree-sitter Python API changed between 0.21 and 0.22 (and again at 0.23), so the binding
# style is version-specific. This code targets the 0.25 API:
#
#     Language(tree_sitter_java.language())   # takes a PyCapsule, single argument
#     Parser(language)                        # language passed to the constructor
#
# Under 0.21 the first call is `Language(ptr, "java")` and the parser is configured with
# `parser.set_language(...)`; that form does NOT work here.
#
# HOW TO VERIFY A VERSION BUMP. This is now possible, and this is the procedure:
#
#     1. On the PINNED versions, with a clean tree:
#            python3 validation/golden_facts.py --write
#        Confirm `git diff results/parser_golden.json` is empty. If it is not, the working tree
#        was already diverged and the bump would be measured against the wrong baseline.
#     2. Bump the pins here and reinstall.
#     3.     python3 validation/golden_facts.py --check
#        Require ZERO differences. Any output is a behaviour change in the parser, reported at
#        the fact level -- file, type, attribute, before, after.
#     4. Run the four suites as well. --check answers a different question from them: it asks
#        whether the parser extracts the same facts, not whether the verdicts came out the same.
#
# Do NOT use validation/extractor_parity.py for this. Its regex side was deleted in phase 1, so
# `--a parser --b parser` compares the new parser against ITSELF and passes trivially. That is
# what made the previous version of this comment false.
tree-sitter==0.25.2
tree-sitter-java==0.23.5
