# piqs/parser.py parses Java with tree-sitter. Both versions are PINNED, not floated: the
# tree-sitter Python API changed between 0.21 and 0.22 (and again at 0.23), so the binding
# style is version-specific. This code targets the 0.25 API:
#
#     Language(tree_sitter_java.language())   # takes a PyCapsule, single argument
#     Parser(language)                        # language passed to the constructor
#
# Under 0.21 the first call is `Language(ptr, "java")` and the parser is configured with
# `parser.set_language(...)`; that form does NOT work here.
#
# THERE IS CURRENTLY NO WAY TO VERIFY A VERSION BUMP. This comment used to say "do not relax
# these pins without re-running validation/extractor_parity.py". That instruction was false.
# The harness compared the regex extractor against the tree-sitter one, and the regex side was
# deleted in phase 1 step 4 once it reported parity. What remains is `--a parser --b parser`,
# which compares the parser against ITSELF: after a version bump both sides are the new
# version, so it passes trivially and proves nothing. Running it would produce a green result
# and false confidence.
#
# What is needed is a golden-fact snapshot: dump the parser's extracted facts for all 184
# corpus files to a committed JSON, then diff a bumped parser against it. Parked as a
# PREREQUISITE FOR PARSER PHASE 2 STEP 3, and it belongs there specifically: step 3 (loop-form
# detection) moves verdicts ON PURPOSE. Without a fact-level guard there is no way to tell
# "the new loop detection fired" from "the parser silently regressed" -- the two look identical
# at the verdict level. Steps 1 and 2 expect zero movement, so an unchanged suite is guard
# enough for them; step 3 has no such luxury.
#
# Until that exists: do not bump these pins.
tree-sitter==0.25.2
tree-sitter-java==0.23.5
